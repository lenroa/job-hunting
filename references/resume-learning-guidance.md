# Resume And Learning Guidance

## Resume Advice Structure

Use this structure when analyzing a JD against the user's resume:

```text
简历建议：
1. 立即可改：基于你已有经历，可以把 [经历/项目] 更突出为 [JD 关键词]。
2. 需要补充确认：JD 提到 [要求]，简历里没看到。你是否有相关经历？如果有，建议补到 [位置]。
3. 暂不建议写：如果没有真实经历，不要写 [内容]，可以在学习建议里补。
```

Prioritize:

- Put the most JD-relevant project or role first when resume format allows.
- Rewrite bullets from "做了什么" to "面向什么问题，用什么方法，产出什么结果."
- Pull JD keywords into true experience, especially domain terms, product methods, metrics, tools, and user groups.
- Add quantified results only when the user provides real numbers or confirms estimates are acceptable and truthful.
- Recommend deleting or compressing low-relevance content when it weakens the role fit.

## Bullet Rewrite Pattern

When enough evidence exists, provide sample resume bullets:

```text
原表达：[if available]
建议改为：围绕 [业务/用户问题]，负责 [产品动作]，通过 [方法/协作/工具] 推动 [交付物/上线/结果]，体现 [JD 关键词] 能力。
```

Keep sample bullets honest about ownership:

- Use "负责" only when the user owned the work.
- Use "参与" when the user contributed but did not own.
- Use "协同" when the core work depended on cross-functional alignment.
- Use "支持" when the role was secondary.

## Learning Recommendation Structure

Rank learning suggestions by hiring impact:

1. Must close for this JD: gaps that may block screening or interviews.
2. Useful differentiator: skills that improve conversion but are not mandatory.
3. Long-term growth: broader product manager capability building.

For each learning item, include:

- Why it matters for this JD.
- What to learn first.
- A practical output to create, such as a PRD,竞品分析, data dashboard, prototype, case study, experiment plan, API workflow map, or AI product demo.
- How to truthfully reflect it later, such as "自学并完成 [作品]" rather than claiming work experience.

## Common PM Skill Gaps

Use these only when relevant to the JD:

- Data: SQL basics, metric trees, funnel analysis, cohort/retention, A/B testing, dashboard reading.
- AI products: LLM basics, prompt/product evaluation, RAG workflow, model capability boundaries, AI agent UX, safety and hallucination handling.
- B2B/SaaS: role permissions, workflow modeling, onboarding, activation, renewal, admin console, enterprise stakeholder mapping.
- C-end growth: acquisition, activation, retention, referral, monetization, experiment design.
- Technical collaboration: API concepts, data schemas, system constraints, technical feasibility tradeoffs.
- Product artifacts: PRD, roadmap, user journey, wireframe/prototype, launch plan, release notes, post-launch review.
- Business: pricing, commercialization, ROI, market sizing, competitive analysis.

## Tone

Be candid but encouraging. Say plainly when the JD is a stretch, but convert the gap into a practical action plan. Avoid vague advice like "提升产品思维"; name the specific product skill and the artifact that would prove progress.
